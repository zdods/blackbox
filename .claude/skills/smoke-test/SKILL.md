# Smoke test

Simulates everything a user would do by hand, against the **real** stack (no
mocks): the bastion + Postgres in Docker, plus a real `blackhaul-daemon` binary
connecting over WebSocket and serving a temp directory. It then drives the
console API through the full journey and asserts each step, printing a
`N passed, M failed` summary.

## How to run

```bash
bash .claude/skills/smoke-test/smoke-test.sh
```

Run it from the repo root. It is self-contained: it builds, runs, asserts, and
tears everything down (containers, volumes, temp dirs, the background daemon) on
exit via a trap. A clean run ends with `36 passed, 0 failed` and exit 0.

**Prerequisites:** `docker` (daemon running), `go`, `curl`, `jq`. The TOTP codes
for the 2FA flow are generated by `totpgen/` (a tiny Go helper that uses the same
`pquerna/otp` library as the bastion, so codes always match); it lives in this
`.`-prefixed dir, so `go build ./...` ignores it.

It sets a stable `JWT_SECRET`, so the run also exercises the **encrypted
TOTP-at-rest** path (not just plaintext quick-start).

## What it covers (keep this in sync with the product)

This is meant to exercise *every* feature — when a user-facing feature is added,
add a step here so the smoke test stays exhaustive.

- **Registration** (single-user, mandatory 2FA): `/api/setup` gate open → fresh,
  `/api/register/totp-setup`, `/api/register`, gate closes after first user.
- **Login**: wrong password → 401; password step → TOTP challenge; wrong TOTP →
  401; TOTP step → session cookie; `/api/me`; unauthenticated `/api/me` → 401.
- **Daemon management**: create (token shown once), list (disconnected),
  rename (`PATCH`), delete.
- **Real daemon**: builds and runs `./daemon`, waits for `connected: true` and
  disk stats in the list.
- **File operations** (proxied to the daemon): list, meta, download (small +
  a 6 MB file via the streaming chunked path, verified byte-identical), upload
  (single-shot, and chunked like the console's 5 MB chunks, verified
  byte-identical), oversize single-shot rejected (413), delete.
- **Security behaviors**: IDOR (unowned daemon id → 404), session revocation
  (old cookie 401 after logout). Wrong-credential paths are covered under Login.

## Interpreting results

- `N passed, 0 failed` + exit 0 → green.
- Any `✗` line names the failing check with `got` vs `want`. The daemon's stdout
  is at `/tmp/smoke-daemon.log` if a file op fails (e.g. the daemon didn't
  connect). The bastion logs: `docker compose logs bastion`.
- If the stack won't start, check `docker` is running and port 8080/5432 are
  free. The script leaves nothing behind on exit, so just re-run after fixing.

## Extending it

The script (`smoke-test.sh`) uses small helpers: `status()` does an
authenticated curl (cookie jar) and returns the HTTP code with the body in
`$BODY`; `check <desc> <actual> <expected>` asserts and tallies. Add new steps
in the matching section and they roll into the pass/fail count automatically.
